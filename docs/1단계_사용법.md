# 1단계: 프레임 찾기 + Z 순서 번호 표시 (출력 없음)
> 개발 기록입니다. 이 문서의 `ZF`, `ZFCLR` 명령은 현재 `PDFMERGE` 하나로 합쳐졌습니다. 사용법은 저장소의 `README.md`를 보십시오.

## 준비
- AutoCAD LT는 **2024 이상**이어야 LISP가 실행됩니다(LT 2023 이하는 LISP 자체가 없음).
- 파일: `lisp/zframe.lsp`

## 실행 순서
1. 도면을 열고 프레임이 있는 **배치탭**으로 이동.
2. 뷰포트 안이 활성 상태(뷰포트 테두리가 굵게 표시)라면 뷰포트 바깥을 더블클릭해서 용지 공간으로 전환.
3. 명령 `APPLOAD` → `zframe.lsp` 선택 → [로드] → [닫기].
   - "로드됨. 명령: ZF ..." 메시지가 보이면 성공.
4. 명령 `ZF` → 노란 ㄱ자 표시 하나 클릭 (어느 모서리 것이든 상관없음).
   - 클릭한 ㄱ자를 **견본**으로 삼아, 현재 배치탭에서 아래 조건이 모두 같은 것만 찾습니다. 레이어는 보지 않습니다.
     - LWPOLYLINE, 점 3개, 열린 선, 곡선 구간 없음
     - 가로 선분 1개 + 세로 선분 1개
     - 색상이 견본과 같음 (견본 색이 BYLAYER면 색 조건 없음)
     - 두 팔 길이가 견본과 같음 (허용 오차 `*ZF-TOL-PT*`)
5. 결과 확인
   - 각 프레임에 빨간 사각형과 번호(1, 2, 3 …)가 그려집니다. 레이어 `ZF_CHECK`, 플롯 안 함.
   - 짝을 못 찾은 왼쪽위 꼭짓점에는 `?`가 표시됩니다.
   - 명령창에 견본 정보(팔 길이·색), 후보 개수, ㄱ자 통과 개수, 탈락 사유별 개수, 꼭짓점 개수(유형별), 프레임 목록(좌표·크기), 실패 사유, 처리 시간이 출력됩니다.
6. 표시 지우기: 명령 `ZFCLR`.

## 확인해 주실 것
- 프레임 개수가 실제 장수와 같은가?
- 번호가 Z 순서(위 줄 왼쪽→오른쪽, 다음 줄 …)인가?
- 빨간 사각형이 도곽 모서리에 맞는가?

## 문제가 있을 때 알려 주실 정보
1. AutoCAD 제품과 연도 (예: AutoCAD LT 2025)
2. 명령창 출력 전체(F2로 텍스트 창을 열어 `[ZF]` 줄부터 복사)
3. 한글이 깨져 보이면 그 사실과 `LISPSYS` 명령을 입력했을 때 나오는 값
4. 가능하면 화면 캡처

## 설정값 (`zframe.lsp` 맨 위)
| 이름 | 기본값 | 의미 |
|---|---|---|
| `*ZF-TOL-PT*` | 0.5 | 꼭짓점 일치, 같은 행/열 판단, 가로·세로 판단, 견본과 팔 길이 비교에 사용 |
| `*ZF-TOL-ROW*` | 5.0 | 프레임 위쪽 Y 차이가 이 값 이하면 같은 줄 |

값을 바꾼 뒤 파일을 다시 로드하면 적용됩니다. 기본값은 사용자 측정(어긋남 약 0.1)을 기준으로 한 임의 설정입니다.

## 알려진 제약
- 도면 안에 견본과 색·팔 길이가 같은 다른 ㄱ자 폴리선이 있으면 후보에 섞입니다. 네 모서리가 직사각형으로 맞지 않으면 프레임이 되지 않지만, 우연히 맞으면 잘못된 프레임이 생길 수 있습니다.
- 블록 안에 있는 ㄱ자는 찾지 않습니다(클릭하면 "INSERT (LWPOLYLINE 아님)"으로 표시).
- LINE 두 개로 된 ㄱ자는 더 이상 찾지 않습니다.
- 시험용 도면 `docs/zframe_test.dxf`: `Layout1` 탭에 프레임 13장(5·5·3장)과, 걸러져야 할 방해 객체 5개(팔 길이 다름, 색 다름, 닫힌 선, 곡선 구간, 가로+세로 아님)가 격자 위쪽에 있습니다. 정상이면 프레임 13개, 탈락 4개(색 다른 것은 후보에서 미리 제외되어 탈락 목록에 안 나옴)입니다.
- 배치탭 UCS가 World가 아니어도 저장 좌표(WCS)를 그대로 쓰므로 영향이 없을 것으로 예상하나, 실제로 확인하지 않았습니다.
